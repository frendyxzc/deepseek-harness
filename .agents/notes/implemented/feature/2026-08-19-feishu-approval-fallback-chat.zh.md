# Agent Note: 飞书审批回退聊天——应答非飞书触发会话的审批

Status: implemented

[English](2026-08-19-feishu-approval-fallback-chat.md) | 中文

## 问题

[审批卡片决策](2026-08-18-feishu-approval-cards.md)把应答绑定在飞书聊天绑定关系上：`dsh-feishu-approval` 只认领经 `feishu/chat-agent` 通告的 agent 及其 subagent 后代的审批请求，其余一律经 `next()` 委托。从别处触发的会话——Web GUI、headless 运行、ACP 自动化——没有绑定关系，其审批只会到达本地应答器。在飞书聊天中工作的操作者无法审批它们：一次从 Web GUI 触发的插件安装引发了权限审批，却始终没有到达操作者正在关注的飞书聊天。

## 决策

`dsh-feishu-approval` 接受一个可选的 `fallbackChatId` 配置字段。每个审批请求的聊天解析遵循固定顺序：agent 会话已绑定的聊天优先；其次是配置的回退聊天；两者都没有时，该请求经 `next()` 委托。回退卡片与所属聊天卡片完全一致——同样的一次性 nonce、同样的点击校验（聊天校验把点击绑定在回退聊天上）、同样的超时、中止、处置与无法送达时的委托——因此路由变化不新增任何结算路径。空的 `fallbackChatId` 在加载时响亮失败，与 `timeoutMs` 的校验一致。

## 考虑过的替代方案

**广播到接收路由见过的每个聊天。** 否决：路由只知道发送过消息的聊天——新进程一个都不知道，而恰恰是那时审批最需要到达——并且重复的卡片让一次决策的点击面成倍扩大。

**由 Web GUI 应答器转发未绑定的审批。** 否决：把 Web 宿主与飞书传输耦合在一起；应答器链才是扩展点，把路由配置放在飞书消费方上使 seam 保持提供方可替换。

**在创建时把非飞书会话绑定到某个聊天。** 否决：`chatBySession` 描述的是会话运行在哪里；把一个 Web GUI 或 ACP 会话绑定到聊天，会向 `feishu/chat-agent` 的每个消费者虚报路由。

## 结果

- 一个配置字段即可把每个工具审批——包括 Web GUI、headless 与 ACP 会话——路由到飞书聊天；省略它则保持委托给下一个应答器。
- 点击校验保留其聊天检查：回退卡片只能由回退聊天内部的点击结算。
- 回退聊天为自己没有触发的会话做决策；卡片上的 session id、工具名与理由是它收到的全部上下文。
