本模块由三个并列的 package-group 组成，均基于 `@deepseek-ai/cordis` 的 Service/Context 机制暴露能力：
- `packages/host/`：以抽象 Service 定义能力边界（如 `DirectoryPicker`、`SandboxProvider`），再由多个具体包实现并注册到同一 `ctx` key。其中 `directory-picker` 定义 `native`/`browse` 两种能力形态的判别联合类型，`directory-picker-native`、`directory-picker-browse`、`directory-picker-auto` 分别作为原生 OS 对话框、浏览器内浏览、自动探测后挂载后端的三种实现；`webserver` 提供命名路由与升级处理，`frontend-static` 在其 fallback seat 上托管 SPA 静态资源；`plugin-inventory` 只读投影 Loader 当前条目。
- `packages/sandbox/`：`sandbox/` 定义 `SandboxProvider.confine(argv, policy)` 抽象及 `read-only`/`workspace-write`/`danger-full-access` 模式与 `ConfinedArgv` 返回结构；`sandbox-local/` 按平台选择 bwrap→Landlock、Seatbelt、Windows 受限令牌等后端；`sandbox-policy/` 集中解析部署默认值与会话级覆盖；`sandbox-windows-acl/` 通过 FFI + C++ ABI probe 实现 Windows 写限制，被 `sandbox-local` 作为 win32 后端挂载。调用链为 consumer → sandbox 策略解析 → 平台后端 → 系统原语，失败时通过 `escalation.ts` 支持一次性用户批准重试。
- `packages/runtime-diagnostics/invariants/`：提供 `InvariantRegistry` 服务，各包在 `./invariant` 伴生文件中注册检查，由全局开关与 package-name 正则 allowlist/blocklist 控制是否运行，违反时抛出带 `packageName` 的 `InvariantError`。
依赖方向单向：host 与 sandbox 不依赖 invariants；invariants 仅依赖 cordis 与 schemastery；各子包之间通过 Cordis 上下文键解耦，而非直接 import。
