本模块由三个并列的 Cordis 插件组成，每个插件均遵循 `src/index.ts`（Host 侧）+ `src/client/index.ts`（Browser 侧）的双入口结构，并通过 `tsconfig.client.json` / `tsconfig.host.json` 分别编译到 `lib/`。

- connection：Host 端通过 `apply` 注册 `/api` 前缀路由，使用 `http-bridge` 将 HTTP 请求桥接到 `HostConnectionService`，并在路由层执行 `assertTrustedAuthority` 信任主机白名单与 `BrowserAuth` 认证；同时暴露 `RpcId`、`transportError` 及 RPC schema。Browser 端 `client/index.ts` 根据 URL 中的 `fixture` 参数选择 fixture 或真实 HTTP 传输，构造 `ConnectionController` 管理连接生命周期，并通过全局 `__DSH_TRANSPORT__` 钩子让宿主注入自定义 fetch/stream/loadBundle 能力，最终将 `ctx.connection` 服务提供给上层。
- hmr：Host 端以固定间隔 `statSync` 轮询已构建的客户端 bundle 元信息，对比 mtime/size 变化后调用 `ctx.clientModules.rebuilt(id)` 并经由 SSE `/plugins/events` 广播 `{type:'rebuilt'}` 帧；Browser 端订阅该 EventSource，按 invalidate → prefetch → registry-first teardown → removeOwnedStyles → entry.refresh() 的顺序串行执行热替换，保证 CSS 注入顺序与 Loader 状态一致。
- locale：Browser 端维护 `LocaleRuntime`，封装字典注册、BCP 47 风格语言注册、回退链校验与不可变 `LocaleSnapshot` 发布，并通过 `ctx.slots.installLocale` 暴露给渲染层合成 `t` 函数；Host 端仅负责在 settings provider 可用时注册 `LOCALE_SETTINGS_NAMESPACE` 配置段，实现跨进程的语言偏好持久化。

依赖方向单向向外：connection 不依赖 hmr/locale；hmr 依赖 client module loader 提供的 graph/artifact API；locale 依赖 dsh-client-ui-slots 与 dsh-settings，三者通过 Cordis Context 服务解耦。
