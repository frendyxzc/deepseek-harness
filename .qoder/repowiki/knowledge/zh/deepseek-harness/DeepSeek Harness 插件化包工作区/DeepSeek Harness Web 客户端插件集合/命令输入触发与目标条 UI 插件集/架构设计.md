三个并列的 npm 包（`ui-commands`、`ui-input-trigger`、`ui-goal`）均遵循同一插件形态：根 `src/index.ts` 暴露空 `apply()` 作为宿主端桩，真正的浏览器逻辑通过 `package.json` 的 `exports["./client"]` 与 `dsh.client.inject` 声明由 Loader 自动发现并挂载。

- `ui-input-trigger` 是底层能力：`core/menu.ts` 维护无 React/DOM 依赖的纯函数菜单状态机（`menuReduce`），`controller.ts` 将检测（`detect.ts`）、分组、高亮与 pick 路由封装为 `InputTriggerController`，`service.ts` 注册到 `ctx.inputTriggers`；UI 层 `MenuView.tsx` 通过 `slots.inject('conversation.input.overlay', ...)` 以 `order: 0` 注入对话输入覆盖区。
- `ui-commands` 建立在 `inputTriggers` 之上：`service.ts` 中的 `CommandUiRuntime` 实现 `Service`，维护 session 级目录缓存（`directory.ts`）、贡献者注册表（`register/decorate`）、模糊匹配评分（`fuzzyScore`/`fuzzyCandidates`）与 per-session `PopupSelectController`；它向 `inputTriggers` 注册 `/` 源并在 `matchEnter/matchSpace` 决策表中分流到 popup、leadingInput claim 或 detached execute，同时监听 `commands/change`、`agent-preset/selected`、`connection/reset` 刷新目录；UI 通过 `PopupSelectView.tsx` 以 `order: 1` 注入同一 overlay 插槽。
- `ui-goal` 是纯投影式表面：`GoalBar.tsx` / `GoalDock.tsx` 仅消费 `useProjection('goal')` 的快照，不持有本地 store；`client/index.ts` 在 `conversation.input.dock`（`order: 10`）注册 GoalBar，并通过 `ctx.remote.goals.*` 的 CAS 引用（从 `sessions.binding(sessionId).session.projections.faceOf('goal').getSnapshot()` 读取）执行 edit/pause/resume/clear 四个变异动词。

依赖方向单向向下：`ui-commands` → `ui-input-trigger`；三者均通过 `@deepseek-ai/cordis` 的 `Context` 扩展（`commandUi`、`inputTriggers`）和 `dsh-client-ui-slots` 的 `LocaleNamespaceMap` 类型合并来接入宿主能力，彼此之间无直接 import。
