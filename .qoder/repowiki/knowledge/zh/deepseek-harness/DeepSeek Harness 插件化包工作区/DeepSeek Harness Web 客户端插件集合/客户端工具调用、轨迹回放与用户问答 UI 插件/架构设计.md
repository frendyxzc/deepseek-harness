本模块由三个独立的 npm 包组成，均遵循相同的 Cordis 插件形态：根 `src/index.ts` 暴露空 `apply()` 作为宿主加载入口，真正的浏览器逻辑集中在 `src/client/index.ts`，并通过 `package.json` 的 `dsh.client.inject` 声明依赖注入的服务（如 slots、locale、uiSession、uiConversation、remote 等）。

- `ui-tool`：注册 `conversation.chat.node`（key=`tool-call`）和 `conversation.details.tool` 两个 slot，挂载 `ToolCallTree` 与 `ToolDetails`；通过 `ctx.plugin(...)` 动态注册 read/search/file-mutation/web/todo/ask-question/bash-sample 等原子 toolview，每个 toolview 以独立子包形式实现 keyed 渲染。
- `ui-trajectory`：向 `conversation.view` slot 注册 id=`trajectory` 的标签页，使用 `uiConversation.binding(sessionId).target('trajectory')` 订阅轨迹快照；通过 `registerTrajectoryMessageDefinition / AssistantDefinition / ToolDefinition / CompactionDefinition / RequestHeaderDefinition` 将各阶段事件投影为统一的 `TrajectorySnapshot`，并由 `TrajectoryTable/TrajectoryTimeline/TrajectoryTurn` 等组件渲染；使用 `@tanstack/react-virtual` 做虚拟行。
- `ui-user-questions`：在 `conversation.composer` chain 中注册一个 selector 路由到 `QuestionComposer`，同时监听 `user-questions/request` remote event，用 `PendingQuestion` 封装待回答请求的生命周期（answer/cancel/abort/delegate），并区分 `plan-review` 意图走 `PlanReviewPanel` 决策卡片。

三个包之间无直接依赖，仅通过共享的 `@deepseek-ai/dsh-client-ui-*` 槽位协议与 `@deepseek-ai/cordis` Context 通信，依赖方向单向指向这些基础包。
