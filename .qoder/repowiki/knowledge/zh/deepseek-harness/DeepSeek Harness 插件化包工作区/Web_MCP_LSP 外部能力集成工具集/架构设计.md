本模块由三个并列的能力族组成，每个族遵循相同的“服务层 + provider 实现 + 工具层”三段式架构：
- web/：`web/` 包提供 `ctx.web` 服务（`WebRuntime`），维护 search/fetch 两类 provider 注册表并在执行时按配置 id 或唯一可用者选择 provider；`web-search-exa|perplexity|deepseek/` 各自实现搜索 provider，`web-fetch-http/` 实现 HTTP fetch provider；`tool-web/` 暴露 `web_search`、`web_fetch` 两个模型工具，仅持有 schema、提示词、超时与输出字符上限等策略，不感知具体 provider。
- mcp/：`mcp-client/` 作为单一插件连接外部 MCP 服务器（stdio 或 streamable-http），通过 `connection.ts`/`transport.ts` 管理生命周期与自动重连，把远端工具以 `mcp__<serverName>__<rawName>` 的命名空间化名称注册到 `ctx.tools`，并做环境变量清洗与 serverName 冲突检测。
- lsp/：`lsp/` 包提供 `ctx.lsp` 服务（`Lsp`），按文件扩展名路由到 provider，只暴露 goToDefinition/findReferences/goToImplementation/hover 四个读操作；`lsp-stdio/` 是 stdio provider 实现，驱动本地语言服务器进程并通过 `ctx.fs`/`ctx.subprocess` 读写；`tool-lsp/` 暴露唯一的 `lsp` 模型工具，负责 schema、prompt 与结果渲染。
依赖方向严格单向：tool-* → 服务层 → provider 实现；provider 之间互不依赖，通过统一的 `Context` 注入点（`ctx.tools`、`ctx.web`、`ctx.lsp`）解耦。所有能力均基于 `@deepseek-ai/cordis` Service 框架，使用 `ctx.effect` 管理 fiber 作用域的生命周期与清理。
