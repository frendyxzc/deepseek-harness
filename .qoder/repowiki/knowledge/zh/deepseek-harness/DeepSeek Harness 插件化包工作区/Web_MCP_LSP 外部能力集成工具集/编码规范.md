- 每个能力族都采用“服务层定义 ctx 扩展 + provider 接口 + 多个 provider 实现 + tool-* 暴露模型工具”的分层结构，工具层只持有 schema/prompt/限额，不直接调用 provider。
- Provider 通过 `registerXxxProvider` 方法向服务注册，返回一个同步 disposer；注册失败（重复 id、无效参数）在变更前 fail-loud 抛出结构化错误，保证原子性。
- 配置对象使用 `schemastery` 的 `z.object`/`z.union` 声明，并提供同名 `Config` 常量用于运行时校验与默认值填充，同时导出对应的 TypeScript 类型。
- 插件入口统一导出 `name`、`inject`、`apply(ctx, config)` 三个成员，由 Cordis 加载器发现并挂载到对应上下文键（`ctx.tools`、`ctx.web`、`ctx.lsp`）。
- 错误统一继承自 `HarnessError` 并以字符串 code（如 `WEB_PROVIDER_UNAVAILABLE`、`LSP_CONFLICT`、`MCP_*`）区分，调用方按 code 分支而非解析 message。
- 资源释放通过 `ctx.effect` 注册 fiber-scoped 清理函数，disposer 在 fiber 结束时自动执行，避免手动 teardown。
