本模块由三个并列的能力族组成，均遵循 Cordis Service Definition / Provider / Consumer 的分层约定，并通过 `ctx` 扩展暴露能力。

- credentials：`credentials/` 定义抽象 `CredentialProvider`（参考键 `CredentialRef` 与记录键 `CredentialKey` 双键空间、`resolve/describe/set/unset` 与 `readRecord/modifyRecord/listRecords/deleteRecord` 记录操作、`notifyUpdated/notifyRecordUpdated` 事件扇出）；`credentials-local/` 实现本地 YAML + 环境变量覆盖的默认提供者；`authorization/` 提供需人工交互的授权流注册表。三者通过 `@deepseek-ai/cordis` 的 `Context.credentials` 注入。
- settings：`settings/` 定义抽象 `SettingsProvider`，维护命名空间注册表、三层合并（schema 默认 → base → 用户层）、序列化写队列、revision 冲突检测与 `settings/updated` 事件；`settings-file/` 将每个命名空间持久化为单一 YAML/JSON 文档并热监听外部编辑。通过 `ctx.settings` 暴露。
- storage：`storage/` 作为 hub，提供 `BackendRegistry` 与数据表单挂载点 `StorageForms`；`storage-domain/` 是唯一的域数据表单，通过 `defineDomain` 声明表结构与 zod schema，按路由选择后端并打开为带变更事件的 `Domain`；`storage-json` 与 `storage-sqlite` 分别以 JSON 文件与 SQLite 实现 `StorageBackend.kv` 契约。通过 `ctx.storage` 与 `ctx.storageDomain` 暴露。

依赖方向单向：consumer → service definition → provider implementation；domain form 依赖 backend registry，backend 不反向依赖 domain。各包独立 `package.json` + `tsconfig.json`，编译产物位于 `lib/`，测试位于 `tests/`。
