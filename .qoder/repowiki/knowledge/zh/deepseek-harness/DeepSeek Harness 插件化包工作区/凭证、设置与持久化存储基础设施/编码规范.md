- 每个能力族以抽象 Service 类（`CredentialProvider`、`SettingsProvider`、`Storage`）定义公共接口，具体实现放在同名或 `-local`/`-file`/`-json`/`-sqlite` 后缀的子包中，通过 Cordis `Context` 扩展注入。
- 对外暴露的标识符（如 `credentialRef`、`credentialKey`、`settingsNamespace`）采用构造函数式工厂配合正则白名单校验，失败时抛出 `TypeError`，并提供对应的 `isXxxName` 判断函数。
- 写路径统一采用“先验证再持久化”的模式：settings 通过 `cloneJsonShaped` 在写入前做 JSON 形状校验与循环引用检测，credentials 的 `modifyRecord` 以 read-decide-replace 原子更新保证并发安全。
- 变更通知通过 `ctx.events.dispatch('emit', ...)` 逐个调用监听器，捕获非 INVARIANT 异常并 warn 日志，最后若收集到 INVARIANT 错误则重抛，确保单个监听器失败不会阻塞其他监听器或持久化结果。
- 每个子包目录结构一致：`src/` 源码、`lib/` 编译产物、`tests/` 测试、`README.md`/`README.zh.md`/`README.i18n.yaml` 多语言说明、`package.json` + `tsconfig.json` 独立构建单元。
- 通过 `declare module '@deepseek-ai/cordis' { interface Context { ... } }` 在各自包的入口文件中扩展 Context 类型，使 `ctx.credentials`、`ctx.settings`、`ctx.storage`、`ctx.storageDomain` 成为类型安全的注入键。
