本模块由两个并列的 npm 包组成：
- `@deepseek-ai/dsh-llm`（`packages/llm/llm/`）：核心运行时。`src/index.ts` 导出 `LlmRuntime`（继承自 `@deepseek-ai/dsh-typert-protocol` 的 `TypertRemoteService`），作为 Cordis 上下文中的 `ctx.llm` 服务，维护 `adapters` Map、可配置提供者目录 `directory` 和模型发现回调 `discoveries`。通过 `registerAdapter` / `registerConfigurableProviders` / `registerModelDiscovery` 进行全量原子替换（返回带 `replace()` 句柄的 disposer），并以 `llm/adapters-updated` 事件广播拓扑变更。`LlmAdapter` 抽象类定义 provider 边界（`stream`、`prepareCall`、`resolveModel`、`listModels`、`imageRequestPricing`、`providerRetryPolicy`），具体实现由外部 adapter 注入。调用路径为 `prepareCall` → `resolveModelInfo` → `resolveCallWithInfo`（校验 reasoning effort / maxTokens 默认值）→ `adapterStream`（按 model 的 inputModalities 投影图片消息）→ 经 `llm/stream` 水门拦截（供重试、回放、路由等中间件消费）。错误统一封装为 `LlmError`（继承 `HarnessError`），使用稳定 `code` 字符串（如 `NO_ADAPTER`、`DUPLICATE_ADAPTER`、`INVALID_PREPARED_CALL`、`UNSUPPORTED_REASONING_EFFORT`）。
- `@deepseek-ai/dsh-deepseek-llm-api-extensions`（`packages/llm/deepseek-llm-api-extensions/`）：轻量扩展注册表。`DeepSeekLlmApiExtensionRegistry` 在 `ctx.deepseekLlmApiExtensions` 下维护 `field → provider` 映射，`prepare(request)` 并行调用所有 provider 的 `prepare`，将返回值结构化克隆并递归冻结，再聚合可选的 `accept()` 回调并通过 `acceptAll` 统一提交，失败时抛出 `AggregateError`。
依赖方向：两个包均依赖 `@deepseek-ai/cordis` 获取 Context/Service/effect；核心运行时额外依赖 `dsh-typert-protocol`、`dsh-invariants`、`dsh-timeout`、`dsh-brand`、`dsh-attachment`、`schemastery`、`zod`；扩展包仅依赖 `dsh-invariants`，不反向依赖核心运行时，形成单向解耦。
