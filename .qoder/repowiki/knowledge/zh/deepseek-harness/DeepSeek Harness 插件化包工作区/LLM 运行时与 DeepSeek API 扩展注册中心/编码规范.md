- 对外暴露的可变状态一律通过返回 disposer + `replace()` 句柄的方式管理，并在 effect 析构中清理，确保注册/替换是原子且可回滚的。
- 所有输入参数在进入业务逻辑前进行严格校验，失败时抛出带稳定 `code` 字符串的 `LlmError`（如 `INVALID_ADAPTER`、`DUPLICATE_DIRECTORY`、`INVALID_PREPARED_CALL`），而非直接 throw 原生 Error。
- 从 adapter 返回的模型元数据在 `normalizeModelInfo` / `listModels` 中集中校验并 detached 副本，禁止外部持有 adapter 内部对象引用。
- 请求对象在准备阶段通过 `structuredClone` + `deepFreeze` 深冻结，配合 `callConfigEquals` 比较，确保 prepared call 只能被精确匹配的一次性分发。
- Cordis 事件发射采用 try/catch 包裹每个 listener，将非 INVARIANT 异常降级为 warn 日志，避免单个监听器故障阻断拓扑更新。
- 扩展点通过 `Map<string, Provider>` 注册并以 field name 为键，重复注册抛错；prepare 阶段并行执行所有 provider 并用 `Promise.allSettled` 聚合 accept 回调结果。
