模块由三层组成：
- 构建入口层：`vite.config.ts` 定义双入口（`index.html` 主页面、`src/preview.ts` 独立 worker 引导），通过自定义插件 `rejectStandaloneServe` 禁止裸 Vite serve，`clientDocumentTitle` 注入标题，`emitPreviewPage` 在构建后把 bootstrap chunk 插入 `dist/preview.html`；Rollup 手动分块将 katex/shiki/micromark 等重型依赖抽到 `vendor` chunk，语法高亮 grammar 按包名路由到 `assets/langs/`，字体走 `assets/fonts/`。
- 运行时层：`src/main.ts` 仅实例化 `AppWebEntry` 挂载到 `#root`，`src/preview.ts` 通过 `@deepseek-ai/dsh-experimental-webworker-runtime` 选择并连接 worker host；`node-module-stub.ts` 桥接 `node:module` 以浏览器化 Cordis Loader。
- 测试层：`tests/scaffold.ts` 是核心——用 Cordis `Loader` + `Include` + `Group` 拼装与生产一致的 composition（base/web-app patch.yml），通过临时 `persistenceRoot`、`harnessHome`、`workspaceCwd` 隔离世界，支持 replay/record/refresh 三种 `$DSH_SNAPSHOT` 模式，配合 `dsh-session-snapshot` 做会话 JSONL 归一化比对；每个 `.e2e.ts` 对应一个场景，`tests/expected/` 存放 UI/geometry/system-prompt/tool-schemas 等 golden 文件，`tests/snapshots/` 放流式中间态快照；`stress-tests/` 提供性能压测用例。
依赖方向单向：测试 → scaffold → Cordis/客户端库 → apps/web 产物；apps/web 本身只依赖 `@deepseek-ai/dsh-client-web` 及若干实验性 worker runtime 包。
