模块由两个相互依赖的 Hatch 包组成：
- `python/sdk`（`deepseek-harness-sdk`）：对外暴露 `src/deepseek_harness/` 包，`__init__.py` 统一导出高层 API（`DeepSeekHarness`、`Session`、`RunResult`、`DeepSeekHarnessConfig`）与底层模型。
- `api.py` 定义用户级数据类与 `Session.run` 流程：等待 `session.event` 收件箱回执后循环消费通知，直到收到 `session.status=idle` 才结束，并从事件流中抽取最终回复与 finish reason。
- `client.py` 实现 `HarnessClient`，使用 `subprocess.Popen` 启动 dsh 进程，通过独立的 reader/stderr 线程以行式 JSON-RPC 2.0 协议通信；请求-响应通过 `uuid` id + `queue.Queue` 匹配，通知通过带过滤器的订阅队列分发，并维护子 agent 会话父子关系以支持树形通知路由。
- `models.py` 用 Pydantic BaseModel 描述 `IncomingRequest`、`InitializeResponse`、`Notification`、`ServerInfo` 等消息结构；`errors.py` 定义 `JsonRpcError`、`TransportClosedError`、`SdkProtocolError`。
- `python/sdk-runtime`（`deepseek-harness-runtime-bin`）：不发布 Python 代码逻辑，而是通过 `hatch_build.py` 钩子在构建时注入单文件 Node 可执行产物（`runtime/deepseek-harness-sdk-runtime-<plat>-<arch>`）及 ripgrep sidecar，并通过 `package.json` 中的 `platforms.json` 声明支持平台；`__init__.py` 提供 `resolve_bundled_launch_args()`，按 `exe`（生产）或 `node`（开发）模式解析启动参数，并在 `main()` 中强制要求显式 `DSH_HOME`。
- 依赖方向单向：SDK 通过可选 import 从 `deepseek_harness_runtime` 获取运行时路径，若未安装则抛出明确错误提示；构建期通过 `uv.sources` 将 `sdk-runtime` 以 editable 方式链接到 SDK 以便本地调试。
