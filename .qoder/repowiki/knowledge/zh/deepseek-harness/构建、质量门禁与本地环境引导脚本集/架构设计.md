脚本目录按职责分为四层：
- 入口与编排层：`build.ts` 通过 `client-build-environment.ts` 解析构建 profile 并串行执行 `build:lib` / `build:web`；`run-gates.ts` 是核心调度器，定义 `Mode`（ci-primary、coverage、snapshot、windows-* 等）对应的 Gate 有向无环图，内置依赖检测、周期检测、并发池与结果汇总，所有子任务统一经 `pnpmInvocation()` 以无 shell 方式调用。
- 验证与生成层：大量 `verify-*`、`gen-*`、`check-*` 脚本各自负责单一不变量（包清单、Cordis 配置、文档链接、翻译配对、Agent Note 格式、客户端域图等），每个实现文件通常配套同名 `.spec.ts` 单元测试，纯函数逻辑与 I/O 分离以便回归测试。
- 共享工具层：`pnpm-invocation.ts`、`markdown.ts`、`cordis-yaml.ts`、`slot-walk.ts`、`ts-project.ts`、`repo-files.ts`、`translation-links.ts` 等被多个 gate 复用，避免在 gate 中重复实现路径扫描与 YAML/Markdown 解析。
- 本地环境层：`setup-dsh/` 是独立 Bash 工程，`setup.sh` 通过模板渲染生成 `~/.dsh/settings.yaml`、Web profile、TencentDB-Agent-Memory 栈配置，并提供 `--upgrade` 幂等迁移；配合 `start-all.sh` / `stop-all.sh` / `export-env.sh` 管理进程生命周期。
依赖方向单向：gate → verify/gen → shared utils → Node 标准库/第三方库；脚本之间不互相 import 除共享工具外的代码，保证可单独运行。
